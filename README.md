# CUMCM Expert Review · 把国赛论文的薄弱点，变成有证据的修订清单

**一个面向 Codex 的国赛论文模拟评审 Skill。** 从原题出发，核对论文、公式、图表和可见代码，给出六维评分、关键缺陷与修订优先级；有同题官网例文时，进一步做公平对照。

*Evidence-first review for mathematical modeling papers.*

[快速上手](#快速上手) · [评审示例](examples/review-example.md) · [评分口径](references/rubric.md) · [核心工作流](SKILL.md)

## 你会得到什么

一份能回答这三个问题的报告：**现在完成得怎样？什么问题会改变评审结论？下一步修什么？**

| 交付 | 帮你做出的判断 |
|---|---|
| 六维评分与依据 | 各项优势和短板在哪里，哪些判断仍有不确定性 |
| 同题逐问对照 | 在相同题意、成本、约束和信息边界下，哪篇论证更充分 |
| 缺陷分级 | 区分已证实错误、验证不足和表达问题，优先处理会改变主结论的缺口 |
| 修订清单 | 每项给出证据位置、影响、最小修正建议和完成标准 |
| 条件性竞争力判断 | 分开看技术竞争力与正式提交就绪度，说明判断成立的条件 |

适合国赛训练队在成稿后自查、指导老师准备反馈，也适合开发数学建模 Agent 的人检查生成稿。只有一篇论文也能使用；没有同题对照时，以原题要求和实际证据评审。

## 看一眼评审方式

论文写道“局部残差很小，因此完整轮廓恢复准确”，评审会继续追问：残差覆盖了哪些点？全部扫描并集是否被纳入？缺失段有没有交代？

| 缺陷 | 证据 | 修复与验收 |
|---|---|---|
| 原题要求修正后的完整轮廓，正文仅描述局部修正 | 当前正文未交付完整结果；可见实现分别输出原曲线和局部修正参数，尚无修正回写证据 | 交付修正后完整曲线、分段参数与覆盖映射；核对连续性及修正前后残差 |

这是实际评审发现的匿名化改写。局部拟合良好可以成立，但还不足以证明整题完成。[查看完整示例与证据边界 →](examples/review-example.md)

## 快速上手

需要可加载本地 Skill 的 Codex 环境、Git，以及该仓库的访问权限。这个仓库本身是 Markdown 工作流，无额外依赖安装器；PDF 读取、联网核验和代码复算使用宿主环境已有工具，实际能力及权限以该环境为准。

### 1. 安装

将**仓库根目录**直接放入个人 Skill 目录。以下初装命令会在目标路径已存在时停止，不覆盖已有安装或本地修改：

```bash
if [ -e "$HOME/.codex/skills/cumcm-expert-review" ] || [ -L "$HOME/.codex/skills/cumcm-expert-review" ]; then
  echo "目标路径已存在，请先检查现有版本与本地修改。"
else
  mkdir -p "$HOME/.codex/skills"
  git clone https://github.com/alexy-dot/cumcm-expert-review.git \
    "$HOME/.codex/skills/cumcm-expert-review"
fi
```

安装后重启 Codex，让新 Skill 被加载。仓库根目录中的 `SKILL.md` 是入口，无需再复制一层 `skills/`。

### 2. 准备材料

把材料放在 Codex 可访问的工作区，并在对话中明确文件位置。例如：

```text
my-review/
├── paper.pdf              # 当前论文，必需
├── problem.pdf            # 对应年份、组别和题号的原题，优先提供
├── attachments/           # 原始附件，需要数据核验时提供
├── code/                  # 支撑代码，可选
└── references/            # 同题对照论文，可选；另附可靠来源链接
```

论文可以直接附在对话中，或给出工作区内路径。说明年份、题号、组别和版本；官网对照提供原始展示页链接，若需核实奖级，再提供可靠获奖名单来源。没有代码会标记“未独立复算”，不会自动判数学错误。

### 3. 发起评审

**单篇质量检查：**

```text
请用 $cumcm-expert-review 评审当前工作区的 paper.pdf。
原题是 problem.pdf，原始附件在 attachments/，支撑代码在 code/。
这是[年份][组别][题号]的当前稿。
请逐问检查是否回答完整，给出六维评分、关键证据、竞争力判断和修订优先级。
说明实际阅读和复算范围；默认只评审，不修改论文。
```

**与同题例文对照：**

```text
请用 $cumcm-expert-review 对照评审 paper.pdf 和 references/ 中的同题论文。
原题为 problem.pdf；对照论文的官网展示页链接为：[粘贴链接]。
先分别评价，再统一成本、约束与指标口径进行比较。
每个会改变结论的缺陷请定位到页码、公式、表格或代码行。
请把技术竞争力和正式提交就绪度分别说明，不将官网展示身份直接视为一等奖证明。
```

## 它怎样工作

```mermaid
flowchart LR
    A[原题与当前稿] --> B[冻结版本与比较口径]
    B --> C[阅读正文并核对关键证据]
    C --> D[必要的独立核验]
    D --> E[六维评分与缺陷分级]
    E --> F[条件性判断与修订清单]
```

评审区分三层材料：

- **论文层**：评委可见的正文与附录是否答题完整、推导自洽、结果可解释。
- **复算层**：原始数据、模型、代码和结果能否相互核对。额外代码不能替正文补写答案。
- **提交层**：按目标年度规则检查格式、匿名、支撑材料与 AI 使用披露等要求；不能用后来的规则追溯扣历史稿分。

## 六维评分，先证据后分数

| 维度 | 默认上限 | 核心问题 |
|---|---:|---|
| 题意覆盖与任务闭环 | 15 | 每个小问最终给出可用答案了吗？ |
| 假设与机制 | 15 | 物理、成本、概率和信息边界成立吗？ |
| 模型与方法贡献 | 20 | 方法解决了真实瓶颈，推导成立吗？ |
| 结果正确性与验证 | 25 | 结果符合约束，有可检验支持吗？ |
| 稳健性与决策价值 | 10 | 推荐方案何时失效，代价是什么？ |
| 论证表达与图表 | 15 | 读者能从模型走到结果与验证吗？ |

这些权重是**内部诊断量表，并非官方百分制或获奖分数线**。高分证据、扣分理由及严重程度定义见[评分口径](references/rubric.md)；优化、预测、几何与交付场景的重点核查线索见[证据陷阱](references/evidence-traps.md)。

## 边界与可信度

本项目提供模拟评审，不代表竞赛官方，也不提供真实专家签字或保奖承诺。官网展示身份须与具体获奖标签分别核实；不同题目、组别和版本不能强行混排。证据不足时会缩小结论、给出判断区间或暂缓评分，不编造精确获奖概率。

工作流来自实际论文对照评审，并做过已知缺陷的行为回归检查。这说明它能帮助复查这些风险，尚不构成未知题泛化能力或获奖率的验证。仓库中的示例用于展示输出方式，不附原始论文、OCR 全文或私有项目材料。

仓库不包含遥测或自动上传逻辑；材料如何由模型处理，取决于你使用的 Codex 环境及其数据设置。
